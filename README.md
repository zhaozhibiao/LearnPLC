# ST Workbench

自研 ST 工程站，桌面界面采用 Avalonia，目标运行环境为独立 OpenPLC Runtime v4.3.0。当前只实施 ST；梯形图暂未加入。

工程树支持函数、功能块、全局变量和数据类型拖入代码，自动生成调用及声明，支持实例复用和一次撤销。操作见 [资源拖放说明](docs/project-resource-drag.md)。

新增独立“硬件组态”和“网络组态”：ESI 目录、工程从站、PDO/IO/轴关联、从站顺序、PLC 管理连接和 EtherCAT 网卡配置跨页同步，随工程保存。当前为离线工程组态，连接状态单独读取，尚不下发总线或改写设备网络。见 [组态操作说明](docs/hardware-network.md)。

基础轴控已增加自有 EcMotion v4 接口：九种 ST 功能块、工程轴资源拖入、固定轴绑定、实际反馈和后端激活检查，见 [基础轴控说明](docs/axis-control.md)。独立轴控周期配置仍属第一阶段，尚不会改变控制核心的实时周期，见 [轴控周期说明](docs/motion-cycle.md)。

## 启动

本机需 .NET 10 SDK、Node.js 22 或更新版本。双击 `启动ST工程站.cmd` 或 `连接设备并启动ST工程站.cmd`，也可运行 `scripts/start.ps1`。在“连接与工具”页确认 SSH 地址 `192.168.1.31`、Linux 用户名 `a`，点击“SSH 连接 Runtime（免密码）”。工程站自动建立仅本机可用的独立 SSH 隧道、读取登录凭证并查询实际状态；无需填写 Runtime 密码，重连或关闭窗口会释放隧道。“账号密码连接 Runtime（直接 HTTPS）”用于另行配置的直接 HTTPS 访问。工程格式为 `.stproj`；源文件按不可变版本保存，保存期间的新编辑不会被覆盖。

首次准备独立编译工具：在 `tools/compiler-adapter` 中运行 `npm ci`，并将固定版本 STruC++ 0.7.0 发行目录放到 `.tools/strucpp-0.7.0/strucpp`。连接与工具页可选择编译器路径。编译工具作为独立进程执行，许可证见 [授权记录](docs/licenses.md)。

## 使用

- 工程树包含程序、函数、功能块、数据类型、全局变量和任务；支持创建、重命名、删除及持久化。
- ST 编辑支持高亮、Ctrl+Space 补全、接口提示、F12 定义和编译错误定位。F7 执行真实独立编译；旧版本错误不会定位到新源码。
- 工程树支持右键添加、打开、复制、重命名、删除和属性。任务引用的程序禁止删除；任务及硬件节点提供配置入口。右侧指令资源库支持分类搜索、左键拖放、双击或按钮插入；自动生成不重名的局部声明，Ctrl+Z 一次撤销。配置工程轴后，“工程轴”分类生成真正可编译的绑定调用。详细操作见 [编辑操作说明](docs/editor-usability.md)。
- ST 编程页可点击“开启 ST 在线监视”，在声明和代码中的变量旁直接显示真实 PLC 值，每 500 ms 采样。先通过 SSH 连接并生成与活动程序一致的候选包；多个功能块实例必须在下拉框选择实例。TRUE 为绿色、FALSE 为黄色；断线、样本过期或工程修改后数值不可用。显示标记不进入源码、保存文件或编译内容。仅显示权威调试映射能够定位的变量，动态数组下标不猜测对应元素。
- 周期任务明确选择程序与周期。当前目标仅启用一个任务，不能把多任务编辑模型解释为已验证的多任务运行。
- 自有硬件页面可导入 ESI XML，查看厂商、产品、修订和 PDO 项，编辑 IO 映射与轴引用。基础轴桥接使用自有 EcMotion 服务；实际 EtherCAT 扫描和实体驱动仍需现场联调。
- 生成候选包包含源码身份、编译产物、任务配置与调试符号。编译、下载、激活、运行是不同状态；本地编译成功不会自动运行设备。
- 点击“下载 / 应用程序”会上传并在 Linux 编译，通过检查后提示重启 Runtime 核心；确认后自动停止原程序（若运行中）、应用新程序并核对停止状态，无需再点激活。取消只保留已编译程序，可通过“应用已编译程序”继续。相同程序已经活动时不重启；通信结果不明时需刷新状态，不自动重试。见 [下载操作说明](docs/download-program.md)。
- 激活后自动查询设备状态，确认已停止的活动程序后启用顶部“▶ 运行”；点击运行才开始执行。“■ 停止”用于正常停止，“刷新设备状态”用于重新确认状态。工具栏会随窗口宽度换行，三个入口在所有页面都可见。
- 同一工程版本重复生成候选包的 ZIP 字节保持一致。设备允许校验后复用相同内容的已暂存版本，旧包仅压缩元数据不同不会阻塞重复下载；不同清单或被篡改的暂存源仍拒绝复用。监视需要打开该活动版本对应的原工程；新建工程即使代码相同，也有不同工程身份。
- 工程树新增路径资源：导入 DXF、原图/连续规划预览、轴映射与加工参数、不可变预存版本，路径随工程保存。右侧“工程路径”可直接拖入版本/摘要绑定的 ST 调用，并沿用检查、候选包和下载流程。连续执行目前仅接通独立 Linux 虚拟后端，真实 EcMotion Continuous 适配尚未实施；未配置匹配后端会拒绝运动候选激活。详见 [连续路径说明](docs/continuous-paths.md)。

设备为 `a@192.168.1.31`，使用已验证 SSH 密钥。隔离 Runtime 位于 `/home/a/.local/share/st-workbench/runtime-v4.3.0`，HTTPS 仅监听 `127.0.0.1:8443`。桌面自动建立 SSH 隧道，使用独立动态本机端口连接；该端口无需保存为配置。安装、证书及账户细节见 [设备安装说明](docs/runtime-user-install.md)。现有轴控工程不因这套安装而替换。

## 验证与边界

运行 `scripts/verify.ps1`（本机已有依赖可加 `-Offline`） 执行桌面构建、工程保存、真实编译器、运行环境适配、运动契约和界面自动验证。界面截图输出到 `artifacts/st-workbench.png`。设备验证必须单独记录，不能由本地模拟测试代替。

原有 Linux 编译、ABI 探针、暂存、激活、独立运行、只读变量和停止已做设备验证；新版下载默认应用流程通过隔离工作流与实际桌面交互测试，本轮未切换现场程序。桌面实例树和趋势读取实际设备数据，修改源码或断线会将数据标为不可用。示例工程 `examples/counter/Counter.stproj` 对应设备上的既有计数器工程。操作步骤和结果见 [验收记录](docs/verification.md)。物理轴运动、实际 EtherCAT IO 下载仍未联调。
