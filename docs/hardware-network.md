# 硬件组态与网络组态

两个页面共享同一份工程从站、IO、轴和网络配置。工程树“硬件”下可以查看从站，点击从站打开硬件属性；点击“网络”打开网络组态。ST 编辑器、资源库、周期配置、下载与在线监视仍沿用原流程。

## 硬件组态

1. 导入设备厂商的 ESI XML。左侧显示设备目录，这不是实物扫描结果。
2. 选择目录设备，填写从站名称和可选别名地址，点击“加入工程从站”。同一个目录设备可添加多个实例；名称必须唯一。别名 0 表示未设置，不给普通 EtherCAT 从站分配 IP。
3. 选中工程从站，修改名称/别名、勾选 PDO 项，点击“应用从站属性 / PDO”。上移和下移调整从站连接顺序，网络页同步更新。
4. 展开 IO 映射与轴配置。IO 可绑定从站及已启用 PDO，方向、类型和位宽必须匹配。选中已有 IO 可修改属性；未绑定的旧 IO 可以继续保留。
5. 轴填写逻辑名、控制器轴名、单位、限位和动态限制，可关联从站。右侧“工程轴”指令资源会同步更新；引用轴的路径和周期配置继续校验关联。

从站被 IO 或轴使用时不能删除；被工程从站使用的目录设备不能移除；已映射的 PDO 不允许直接取消。先解除引用或修改绑定，再应用相应变更。错误操作会保留原工程数据，并在“编译与运行日志”说明原因。

## 网络组态

1. 填写 PLC 的管理 IP / DNS 主机名和 Linux SSH 用户名。直接 HTTPS 地址可选，仅填写地址来源，例如 `https://192.168.1.31:8443`；不用密码或查询参数。
2. 填写 PLC 端用于 EtherCAT 的 Linux 网卡名，例如 `enp2s0`。这里只保存选择，不会改网卡驱动、IP 或路由。
3. 点击“应用网络组态到工程”。验证通过后更新工程草稿和当前连接目标；变更目标时清除旧认证、变量监视和设备版本状态。点击顶部保存才会写入工程文件。
4. 拓扑分别显示“工程站—PLC 管理连接”和“PLC—EtherCAT 主站—从站”。下方从站列表与硬件页同步，选中后可调整顺序或打开硬件属性。
5. 点击“SSH 连接 Runtime（免密码）”使用原有严格主机身份验证和私有隧道。草稿有未应用修改时先应用，不会连接到旧目标。实际连接状态单独显示，不能由工程拓扑推断。

“从当前连接设置读取”只填入编辑字段，之后仍需应用；“清除工程网络配置”移除该工程的网络设定，保留连接与工具页的当前目标。密码、私钥和会话令牌不写入工程或候选。

## 保存与设备状态

配置随 `.stproj` 保存。加载旧工程时不会擅自添加网络或从站配置，也不会把原 ESI 目录设备迁移成实物从站。新配置改变工程硬件身份，旧候选与在线变量随即失效，需要重新检查并生成候选。

配置存在时，候选包含库存摘要覆盖的 `hardware-configuration.json`，状态为 `offline-engineering`。它记录管理目标、目录/从站、PDO 和 IO/轴绑定，并不表示控制器已经应用该配置。

本阶段不扫描实物、不修改 Linux 网络、不启停运动服务、不下发 EtherCAT 或驱动参数。这些操作需要自有控制核心的实际接口，当前页面不会把离线组态显示为成功下发。

界面：[硬件组态](../artifacts/st-workbench-hardware.png)、[网络组态](../artifacts/st-workbench-network.png)。关闭旧窗口并通过根目录 `启动ST工程站.cmd` 重新打开即可使用新页面。
