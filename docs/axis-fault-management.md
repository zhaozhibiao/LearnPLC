# 轴故障与工程管理分离

2026-10-21 已在 192.168.1.31 安装新核心并核对实际运行文件。

## 状态含义

| 状态 | 含义 | 不包含的条件 |
|---|---|---|
| runtimeReady / ControllerReady | 总线和 IO 可用、轴表匹配、采样及通信正常 | 所有轴无故障 |
| motionReady / MotionReady | 当前各轴没有故障或待确认机械状态 | 自动启动许可 |
| 各轴 state / fault | 真实轴运行状态、保护或驱动器故障 | 工程站连接状态 |

轴故障保留 ErrorStop 和具体原因，防止故障消失后自动恢复动作；复位仍需显式请求，实时核心仍逐轴检查使能、回零及运动。
轴故障不再把正常的工程通信、在线变量采样、程序编译、传输或激活身份核验判定为核心离线。

轴桥发现故障轴的新 Enable/Home/MoveAbsolute/Jog 请求时，在申请控制权前返回 2005。
已有运动发生故障时保留失败和真实反馈，不把 Done 当作成功。明确的后端命令拒绝不再杀死工程管理通道，不自动重试。
通信断开、样本失效、所有权失效及未知结果继续按原有保守方式处理。

## 物理组态仍需独立管理

“上传并应用总线组态”还会重启 EtherCAT 核心并改动 PDO/机械配置，继续要求 PLC 停止、轴撤使能且符合硬件安全检查。
这与普通程序包的上传、编译和下载不同；不能通过删除轴保护来绕过硬件重配条件。
当前程序激活还会检查组态摘要、轴清单、设备身份及实际递增采样，轴故障不会代替这些检查。
