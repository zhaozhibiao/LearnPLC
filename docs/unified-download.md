# 程序与组态统一下载

**此文记录旧版自动同步流程。已按用户最新要求改为程序／硬件分开传输，当前操作请看 [常驻工程服务与分范围传输](scoped-engineering-transfer.md)。程序下载不再自动应用组态。**

点击“下载 / 应用程序”即可上传完整工程包、Linux 编译、比较组态、确认并应用。程序包原本就包含工程组态；本次补齐了下载与设备组态应用之间的衔接，无需因 ManifestSha256 不一致再手动上传一遍组态。

## 比较与应用

| 比较结果 | 下载中执行的操作 |
| --- | --- |
| 所需组态与设备一致 | 保留运动核心和轴服务，按原流程切换 PLC 程序 |
| 轴清单不同，实际硬件组态相同 | PLC 停止、轴停稳撤使能后，仅更新用户轴服务，保留运动核心进程 |
| 总线、IO、机械或保护配置不同 | 经受限常驻代理应用硬件，重启运动核心，重新核验反馈及清单 |
| 组态已匹配，但此前编译就绪记录过期 | 重新核验并刷新候选记录，不必再次 make 或修改组态 |

上传和编译期间保留原程序。确认弹窗一次说明目标、当前运行状态、Runtime 重启及组态变化；正文可滚动，窗口可缩放，底部按钮固定。确认后再次检查设备、活动程序、工程和计划身份，才允许停止与更新。计划变化不自动扩大操作范围。

组态更新要求 PLC 已停止、轴已撤使能及停稳、安全输出已确认。轴服务更新的停稳依据是实际加载且指纹匹配的机械配置中的到位策略，不以未应用的新阈值放宽检查。全部轴、循环推进和原生进程身份都必须核验。

成功后保持原来的运行／停止状态。更新结果不明时立即结束，不继续激活、不启动、不自动重试；先查询实际状态。若新轴清单已安装而旧程序仍活动，状态查询与设备端 Start 都会核验旧程序的清单，防止旧 AXIS_REF 使用新映射。

## 接口及范围

普通用户部署端新增只读 `configuration-plan` 和绑定 `configuration_identity` 的 `configuration-apply`。计划绑定候选、实际旧配置、目标配置和操作类型。应用复用部署锁、基线校验及受限硬件 broker，不传输 sudo 密码、不接受自定义服务或执行路径。路径、通信、轴控周期等其他就绪门禁保持有效。

统一组态应用针对显式启用的通用 EtherCAT 配置及已配置的私有 EcMotion 轴桥。未知后端、无效库存、不可确认的原生状态均拒绝执行；保留 ManifestSha256 校验。
