# 通用 ESI 与 Linux 总线组态

工程站现在可以从 ESI XML 保留 PDO 分组、同步管理器、DC 模式及启动 SDO，生成同一个 Linux 原生核心能够加载的组态。ST 仍使用原有 MC 功能块，硬件页保留原有布局。

## 操作

1. 重启工程站，在硬件组态导入 ESI 并添加从站。旧工程若只有扁平 PDO 信息，需要重新导入完整 ESI。
2. 展开通用 EtherCAT 运行配置，启用组态并设定总线周期；选择从站的 PDO 分组、DC 模式及驱动适配配置。
3. 绑定工程轴，填写编码器/传动/工程单位、行程和动态参数，以及回零、实速保护、跟随误差和到位条件。核实后勾选机械与安全参数确认；修改相关参数会撤销确认。
4. 检查并编译工程。生成包含 `ethercat-runtime.json`、`machine-config.json`、`io-map.json`，三者哈希绑定于候选程序。
5. 选择左侧“硬件”，点击“下载硬件”。此步骤独立生成组态包，不要求 ST 编译成功，不切换 PLC 程序。轴必须已停稳且撤使能；确认后应用组态、重启运动核心并核验反馈，完成后 PLC 保持停止。
6. 选择左侧程序，点击“下载程序”。自动检查、编译和生成程序候选；设备组态必须已一致，否则提示先下载硬件。确认 Runtime 重启后应用程序，成功后保持程序下载前的运行／停止状态。结果不明不自动重试。

设备会阻止与实际组态或轴映射不匹配的旧程序重新启动。常驻服务、程序与硬件上传说明见 [分范围传输](scoped-engineering-transfer.md)。

Linux 安装路径及当前测试机身份是固定受限配置，尚不支持从工程任意指定 root 可执行程序。初次部署需由管理员安装固定核心及常驻代理，并授权普通用户组；没有增加免密码 sudo 规则。安装与权限说明见 [常驻组态代理](resident-hardware-broker.md)。

## 当前支持边界

- 标准 CiA402 CSP 和已验证身份的 IS620N CSP 适配；设备型号、产品码和修订号必须与在线设备一致。
- 多轴静态绑定、有限行程；模数/连续旋转模式暂时阻止应用。
- 普通 IO 支持 BOOL、INT、REAL；轴拥有的从站暂不同时作为普通 IO 映射。
- 不支持的 PDO 填充、模块插槽、启动转换、数据类型及厂商行为会明确阻止下载。ESI 描述本身不证明机械参数正确，也不意味着任意型号免调试。
- 组态辅助程序先离线解析，再检查停止/撤使能，启动后核验实际指纹、循环推进和安全输出。失败显示未知或停止状态；不声称已经自动回滚到旧组态。

新编写的工程站及适配代码采用 MIT；OpenPLC、编译器、IgH 和其他依赖继续遵循各自许可证，不能由这项功能推导出整个产品可以闭源分发。

可打开 [只读 IS620N 示例](../examples/generic-ethercat/IS620N-Generic.stproj)。示例 XML 是根据已记录实机参数重建的项目测试夹具，并非厂商发布的 ESI。


## 轴故障与管理状态

轴 ErrorStop 与工程管理就绪状态已分离。故障不阻断正常通信、监视和程序管理；硬件重配仍执行独立的停止及安全状态检查。参见 [轴故障与工程管理分离](axis-fault-management.md)。
