# 独立轴控周期：第一阶段

已加入现有“周期任务”页，向下滚动可找到“独立轴控周期”。当前交付的是工程配置、候选包校验和设备只读诊断。**真实 EcMotion 执行适配还未接通，配置尚不能改变实际轴控线程或驱动实体轴。**

## 操作

1. 关闭旧窗口，从根目录“启动ST工程站.cmd”重新打开。
2. 在“硬件与轴”维护工程轴引用。
3. 在“周期任务”勾选“配置独立轴控周期”，选择轴组，填写周期、FIFO 优先级、可选 CPU 编号及连续超时周期数。点击“应用轴控周期到工程”后保存。
4. “核验设备实时状态（只读）”通过现有 SSH 目标查询实际实时内核、PLC 周期线程和独立运动服务调度。它不会应用设置、启停服务或发送轴命令。
5. 检查、生成候选和 Linux 编译仍使用原流程。启用配置时包内增加校验覆盖的 `motion-cycle.json` 和 `workbench-motion-cycle-v1` 标记。执行适配未就绪时明确显示“不可激活”，设备端也会在任何服务/Runtime 写操作前拒绝。

普通 PLC 周期继续绑定用户 ST 工艺程序。轴控周期由运动核心负责插补、总线输出和轴反馈，本阶段没有用户程序绑定入口。未来需要逐周期同步工艺逻辑时再增加受约束的专用入口。

## 校验与状态

范围：周期 100–100000 μs、FIFO 优先级 1–89、CPU 0–1023 或未绑定、连续超时阈值 1–100 周期、轴组 1–64 个现有工程轴。范围仅为配置结构限制，不证明驱动支持任意取值。超时阈值是执行端连续周期超时配置，和 PLC 扫描/命令租约超时不同；它尚未在实体执行端生效。

轴引用和物理轴映射不能重复；配置使用工程轴的实际名称。路径轴必须属于轴组，路径采样周期必须与轴控周期一致；不一致时须生成匹配的新路径版本，不能修改已封存路径。已被启用周期引用的轴禁止直接删除。

工程配置已保存不等于设备已生效。当前界面明确区分实时内核与线程策略；没有实际周期、最大抖动、超时统计接口时显示“不可用”，不会根据填写的周期或虚拟计时生成测量值。查询期间切换工程、修改配置或目标后，过期成功/失败结果都不会覆盖新状态。

旧工程未启用此配置时不增加候选标记/配置文件，不改变旧构建身份。配置进入硬件身份，轴组快照赋值及访问均防御复制。关闭的草稿参数不进入活动候选。
