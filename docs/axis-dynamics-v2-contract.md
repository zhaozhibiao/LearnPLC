# Axis dynamics v2 implementation contract

The existing `workbench-axis-v1` image remains 2576 bytes and uses its original socket/service. Preserve existing ST fixes unrelated to dynamic inputs. The incomplete 64-byte-slot header/shim changes are retained in a separate `tools/axis-bridge-v2` implementation; do not publish a 4112-byte image as v1.

V2: `workbench-axis-v2`, 64 slots, 16-byte scan header, each slot `<QQdddddQ>` = request,kind,position,velocity,acceleration,deceleration,jerk,flags; command4112 bytes, feedback6656 bytes: old 88-byte feedback plus rejected-request/error uint64 values per slot. Worker and library require explicit v2 metadata and a dedicated socket. No length-based protocol detection. V2 exports marker `workbench_axis_v2`; bootstrap uses `STWORKBENCH_AXIS_V2_SOCKET`. Dedicated endpoint `/home/a/.local/share/st-workbench/axis-v2/axis.sock`; v1 remains unchanged. Manifest declares version and image sizes. Deployment must reject mismatched versions/capabilities before stopping or exchanging an application.

Only zero inherits an explicitly configured default. Reject negatives, NaN/Inf, unknown defaults and positive values above engineering maxima, at ST/worker/native boundaries as applicable. Zero jerk inherits configured legacy0 or positive limit; it never disables a positive configured limit. Request inputs are sampled on Execute rising edge, travel with their request identity and remain immutable while Busy. Rejecting a request cannot mutate the current trajectory or safety latches.

Phase1: MoveAbsolute A/D/J, required native capability `workbench_axis_move_profile_v2`. Phase2: MoveVelocity A/D/J and ordinary MC_Stop D/J after a verified jerk-bounded velocity transition exists; required `workbench_axis_velocity_profile_v2`. Do not publish unsupported pins. Protective/emergency disable and bus/timing/limit protection retain priority over ordinary jerk-bounded Stop.

Native protocol v4 remains envelope-compatible; absent command fields preserve legacy semantics. Explicit `motionProfileVersion:2` requires the above capability, strict effective-limit validation, and the same precheck/apply behavior. Cover direct AxisCommandRequest and PlcScanBatchRequest action transmission. Keep motion v1 clients working. Group/path semantics must not silently inherit single-axis changes.

Engineering selects v2 only for programs using dynamic MC parameters (lexer/index-based instance/call detection, excluding comments/string/unrelated function parameters); existing programs retain v1. V2 resources, manifest, package hash, compiler exports, worker capability, private endpoint and activation gates must agree. Axis defaults A/D must be positive, J explicitly nonnegative. Program/hardware consistency checks remain mandatory.

Tests: real ST compilation with old omitted inputs and new named inputs; image handshake/version rejection; rising-edge/Busy immutability; all-slot transport; parameter boundaries and NaN/Inf/overflow; runtime precheck/apply equivalence; nonzero initial velocity, reversal, stopping distance and soft-limit stoppability; no RT allocation/blocking; offline complete native suites. Physical commissioning only after coherent binaries/packages and external approval availability.

Review correction: v2 feedback separates the last accepted owner progress from the latest rejected request. A rejected Stop cannot abort the prior FB, lose its Done proof, assert a Stop lock, or change its native trajectory. Handshake/manifest enforce6656-byte v2 feedback; old5632-byte v1 feedback remains unchanged. V2 was not deployed before this correction.
