# IS620N MCP commissioning test

User requests an ST test program in this workspace authored through the real MCP service, to test the connected IS620N and motor. User confirms motor is unloaded, disconnected from transmission and securely fixed.

1. Query existing engineering/runtime/MCP permissions and true controller capabilities. Read physical slave identity, PDOs, alarm, position units and homing configuration with an explicitly read-only administrator probe. Do not reuse old SV660N identity or unit conversion.
2. Through actual MCP stdio calls create examples/is620n-test/IS620N-Test.stproj, configure one bound engineering axis and 10ms PLC task, write ST test sequence, validate, save and invoke the real compiler. Initial request/arming variables remain false. Read status every scan; latch fault, stop on timeout/cancel and disable at termination. Small reversible motion targets must be anchored to actual position and validated engineering units, never hard-coded machine absolute zero.
3. Check configured Linux motion gateway/core and exact manifest. Existing MCP configuration has no devices, controller socket is absent and native core has a homing interlock; do not bypass these gates or fabricate readiness. Physical controller startup requires real identity/PDO/mechanics and correct rights. Prepare supported deployment only after discovery.
4. Execute physical test only when model/units/reference/core readiness are proven. Record actual feedback and final stop/disable; compilation or a simulator pass is not physical motion verification.

Current independent work may continue while administrator probe is pending. No existing PLC program or configuration is to be overwritten by the test project.
