# 硬件组态与网络组态设计草案

## 页面职责

沿用现有工程树、ST 编辑器、资源库、周期任务和下载流程，将“硬件与轴”整理为“硬件组态”，增加独立“网络组态”。两页读取和修改同一份工程数据，不创建第二套轴或 IO 清单。

硬件组态负责 ESI 设备目录、工程中实际添加的从站、PDO 查看与选择、IO 映射、逻辑轴与控制器轴绑定、位置范围和运动限值。设备目录与已配置从站明确区分：导入 ESI 不能被显示为扫描到实物设备。

网络组态负责 PLC 的管理连接目标、EtherCAT 主站接口及从站连接顺序，展示“工程站—PLC 管理连接”和“PLC—EtherCAT 主站—从站”两条关系。SSH 主机/用户及 Runtime 地址属于管理连接；EtherCAT 使用 Linux 网卡接口和从站位置，不给普通 EtherCAT 从站虚构 IP 地址。

## 第一阶段可操作范围

- 导入 ESI，选择设备加入工程，编辑名称，查看 PDO，添加/删除从站和调整顺序。
- 在硬件页继续编辑 IO 和轴；引用设备、轴或路径时检查关联，阻止留下悬空配置。
- 在网络页配置管理目标和 EtherCAT 接口、编辑从站顺序；硬件与网络两页的从站选择和属性同步。
- 保存/重新打开保留配置；非法地址、重复设备名/站号、重复轴映射、无效网卡名称在应用前明确报错。
- 网络页提供明确的“连接 Runtime”入口，沿用已有 SSH 隧道和认证机制。密码、会话令牌、私钥不进入工程。
- 组态变更使旧候选和在线身份失效，重新检查/生成候选后才能下载。老工程没有新网络配置时，保留既有构建身份与加载能力。

## 在线与设备应用边界

工程组态、连接状态、设备实际状态分别显示。初始页面不会把工程离线配置解释为在线扫描结果或已在控制器生效。

本阶段不自动改写 Linux IP/路由，不启停运动服务，不修改 EtherCAT 主站或驱动的运行配置。已有只读诊断可以保留；真实扫描、IO 下发和从站参数应用必须通过控制核心的实际接口实现，并在就绪时另行加入。当前不可用的操作显示原因，不返回模拟成功。

## 方案比较

推荐两个独立页面，共享工程模型：硬件属性与网络连接各自清楚，适合继续扩展实际总线能力。

备选是在现有“硬件与轴”页增加子选项卡：改动较小，但设备关系和参数仍挤在同一入口。用户已提出独立页面，优先推荐前者。

## 验证

覆盖旧工程兼容、新配置持久化与快照、非法配置应用前拒绝、跨页同步、从站排序/删除关联、网络目标切换后的连接和候选失效。界面验证真实控件操作；需要编译的变化使用既有真实编译器回归。第一阶段验收不驱动实体轴或修改设备网络。
