# 程序与组态统一下载

用户已同意将组态比较、更新和程序应用串在同一次下载中。保留清单身份校验。上传和编译不打断原程序；确认之前不改变设备。只改 ST 时不重启运动核心，仅轴清单变化时只更新普通用户轴桥；物理拓扑、机械参数或 IO 配置变化时由现有受限 broker 应用硬件。

设备提供只读 configuration-plan，返回候选 build_hash、kind（none/axis/hardware）和 identity。identity 绑定候选、所需操作及已验证配置内容。确认后重新查询并比较完整计划，发生变化即拒绝。configuration-apply 要求原程序身份一致、PLC STOPPED、轴已停稳且撤使能；请求携带确认的 configuration_identity，设备在锁内重新比较计划，禁止隐式升级操作。硬件变更沿用现有 broker；轴清单变更保留运动核心，仅停止轴桥、原子更换清单并启动轴桥。两者都要求重新验证真实硬件和新清单能力后才算完成。

桌面在一次可滚动确认中说明目标、PLC 原状态、Runtime 重启、是否需要运动核心重启。确认后核验原状态，停止原 PLC（如需要），应用必要组态，验证就绪，再切换程序。最后核验身份后恢复原运行/停止状态。取消、工程/设备目标变化、身份变化、组态结果不明或就绪检查失败均不继续写操作、不自动重试；可能部分完成时明确提示查询真实状态。

同一程序身份但组态未匹配也必须执行修复，不能提前报告 AlreadyActive。非通用 EtherCAT、路径/通信/周期执行端未就绪仍保留原门禁，不把任意后端故障解释为可更新组态。真实试验不使能或运动电机。

验证包括设备计划分类、清单库存篡改、确认前只读、无权限服务、轴未停稳、计划变化、应用失败/反馈未就绪；桌面 running/stopped、取消、同程序配置修复、全过程身份检查及恢复状态。现有部署、轴、桌面和 MCP 回归必须通过。
