# 轴周期诊断采集

用户已确认加入上一轮提出的同步采样方案。本次落实为独立诊断候选，不改工程站布局、生产服务、保护阈值或运动算法。

采用独立有界记录器：在 EtherCAT 接收并处理过程数据后，保存上一周期发出的目标；轨迹与保护处理完成后，把本周期新目标和同一接收过程映像中的反馈、6062 内部需求、60F4 驱动器跟随误差、6077 转矩记入同一条记录。整数按有符号 Int32/Int16 解码，不经 Float32。记录主站周期编号、计划/实际时间、总线有效性、模式、状态字、错误码以及运动编号。

实时循环仅写预先分配的定长数组，不分配内存、不加锁、不做文件 IO。默认记录 60000 周期，满后停止追加并统计丢弃数；不影响运动或保护。程序正常结束、实时循环与工作线程停止后导出 CSV。可选 CLI 显式开启，未开启时原路径保持不变。缺失或类型错误的诊断 PDO 在使能前拒绝启动。

诊断 PDO 在原 TxPDO 1A00 的五项后附加 6062/60F4/6077，总共八项；RxPDO 不变。使用独立 JSON 组态以及独立构建目录和服务，先检查驱动器未使能时 OP/WKC、PDO 映射和 CSV 连续性，不在本轮新增运动。

软件测试覆盖负数与边界解码、同一条记录的前后目标、缺失/错误位宽及方向、容量上限/丢弃计数、导出列与顺序。设备验证如映射被拒绝，保留错误和未使能状态，不退化为零值假装成功。

记录代表同一主站接收周期，不声称驱动器各对象内部采样时刻完全相同；有效性由 OP/WKC 标识。不会把新增候选覆盖生产安装。
