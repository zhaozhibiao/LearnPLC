# 轴控接口、故障恢复与链路验证设计

日期：2026-11-02。范围沿用用户已确认的方案：保留Python桥与C++实时核心，完善接口、恢复语义和证据，不做语言迁移。

## 行为约定

1. 原生连接超时、截断、错序、重复JSON字段或非法响应后，立即关闭并永久标记该连接不可用；运动结果未知时绝不重试。新连接仅由明确的新通道会话建立。有效的业务拒绝保留连接，允许只读和后续合法恢复请求。
2. 故障原因锁存为固定类别，不记录请求载荷、租约或凭据。区分设备动作拒绝与传输故障；公开通道是否需要重新建立。保留现有保护性停止/释放路径及本地ST错误码，ABI不变。
3. 在非实时通信线程统计原生请求往返次数、失败次数与耗时；不把管理往返耗时当作EtherCAT或驱动器延迟。统计字段仅按现有1秒心跳发布，故障撤销立即发布，不能恢复高频文件写入。
4. 以真实Unix套接字注入超时、截断、错序和有效拒绝，验证关闭连接、无命令重放、会话恢复和数据清空。新增只读链路探针，唯一允许Hello/ReadSnapshot，无控制租约、运动或在线写入。

## 交付边界

v1/v2共同修复传输实现并以同组测试验证，保持原图像/版本及ST接口。设备只读测量与主动破坏性注入分离：注入仅运行在隔离假核心；实际设备仅验证只读链路。发布时保留原文件备份及工程身份，必要重启后恢复原RUNNING/STOPPED状态，不恢复旧动作请求。


## 显式恢复入口

提供普通用户可执行的恢复工具：要求PLC已停止、活动程序身份及库字节一致、实际硬件指纹一致，全部轴有实际撤使能与配置要求的静止证明。驱动故障允许存在，但不能有力矩使能或运动。工具只重启固定Runtime用户服务并验证轴桥，不下载/换程序、不改硬件、不启动PLC、不重发旧动作。核心PID变化、反馈冻结或恢复未确认时拒绝继续。恢复失败保持停止并要求查询实际状态。
