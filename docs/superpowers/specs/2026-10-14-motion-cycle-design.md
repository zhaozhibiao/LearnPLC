# 独立轴控周期，第一阶段

用户批准在原周期配置页统一管理轴控周期，逐步实施。ST 用户程序仍绑定普通 PLC 周期，独立实时循环归运动核心；本阶段不添加任意用户程序到 EtherCAT 循环。

本阶段交付：可选、默认关闭的轴控配置（轴组、微秒周期、FIFO 优先级、可选 CPU、连续超时周期数），工程持久化、校验、冻结及构建身份；启用后候选携带明确执行端配置；Linux 核验候选结构并拒绝尚未支持的执行适配激活。周期页提供只读实时诊断，区分内核、PLC 扫描线程和独立运动服务。实际周期/抖动统计没有数据时标记不可用。

旧工程无配置时序列化、SourceHash/HardwareHash、候选程序身份及包内容保持一致。关闭的草稿设置不进入活动构建身份。启用须选择现有且不重复的轴映射，100–100000 us，FIFO 1–89，CPU 0–1023 或未绑定，超时 1–100 周期。路径采样周期须与启用的轴控周期一致，且路径轴均属于轴组。范围是结构限制，不代表驱动支持这些周期。

Linux 检查只读内核和服务 cgroup 线程策略/优先级/亲和性，不修改调度，不启动服务，不运动。没有真实执行适配/能力证明时 MotionCycleReady=false；虚拟后端不能证明真实轴控就绪。

后续阶段仍需：真实 EcMotion 配置适配、实时调度落实、硬件轴参数关联、运行统计、停止故障联动、连续轨迹输出及实机验证。本阶段不把这些未实现项显示为已生效。
