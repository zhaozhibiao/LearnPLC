# Linux生产Python替换为C++设计

日期：2026-11-02。用户授权范围：所有部署在Linux的本项目生产服务/管理/部署/诊断入口迁移为C/C++，完成验证后删除对应原Python实现。操作系统自带Python不卸载。旧实现仅在迁移验证期间作为对照与回退，禁止提前删除或用Python子进程包装冒充迁移。

## 固定架构

采用C++20。现有C++ EtherCAT实时核心与PLC扫描程序保持独立，不把HTTPS、编译或文件操作并入实时线程。新增linux/native构建根，分别提供轴工作进程、通信工作进程、路径工作进程/MCP运动网关、工程HTTPS服务、Runtime兼容管理主机、部署协调器、特权硬件与启动恢复、隔离/诊断/安装入口。

保留ST v1/v2图像、Unix帧、JSON、HTTPS/WebSocket、工程站和MCP对外语义。Runtime管理主机使用原C++ plc_main及既有IPC，维持safe-mode启动；新主机不等于替换ST编译器或实时轴核心。实现迁移不意味着修改已确认的故障、限位、回零或运动参数。

## 依赖及身份

JSON使用已有nlohmann/json；网络采用成熟的Boost.Beast/Asio与OpenSSL，保留其授权文本和版本记录。独立新代码使用项目MIT授权。现场固定版本 source/LICENSE 已核实为 MIT，Copyright (c) 2026 Autonomy；逐项保留实际源码与依赖的授权记录，不能按 OpenPLC 名称推断所有版本为 GPL，也不能由根目录 MIT 推断所有子组件均为 MIT。

Windows候选包携带明确的C++工作进程源码束，Linux编译后记录源束摘要、ELF摘要、编译器及接口身份；激活校验候选、安装来源和实际执行文件。不能把ELF误当成源码摘要，也不能继续携带Python工作进程。

## 安全与验证

所有未知运动结果不重试。帧截止、私有socket、调用者权限、状态/版本/哈希、原子写入、事务日志和回滚继续有效。恢复需PLC停止和实际撤使能静止证明，不能自动运行旧动作。普通故障保持查询能力。

每组件先建立失败用例、逐条对照已有Python测试和协议，再执行C++测试；实际设备先只读，之后受控切换及小行程验收，恢复原工程/运行状态。旧Python删除条件为完整功能矩阵覆盖、源码包/安装/启动链无Python引用、现场测试和回滚验证通过；测试/历史诊断脚本也须有覆盖或明确退役记录。
