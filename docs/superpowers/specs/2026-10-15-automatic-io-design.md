# 自动 IO 地址与映射表格

用户要求：加入工程从站后自动分配 IO 地址；IO 映射显示为表格；单击工程树的 IO 映射直接显示表格。继续在当前目录和现有硬件页实施。

采用保留已有、补齐缺失策略，不做全工程重新编号。纯 Core 分配器接收硬件和目标从站，返回新增映射与明确的跳过原因，不直接修改对象。已映射的相同从站/PDO/方向不重复分配。类型和位宽须符合既有 PDO 兼容规则；支持现有 BOOL/BYTE/WORD/INT/DWORD/DINT/REAL/LREAL 及已有别名。64 位 LREAL 使用编译器已支持的 L 地址，并将项目地址正则扩展到 L。其他类型明确列出不自动映射的原因，不能缩窄位宽。

输入/输出分别分配，地址编号从 0 起找空闲；按地址宽度对齐，BOOL 使用 X 字节.位（位号 0–7）。为避免别名和混合宽度意外重叠，分配器对已有地址保守预留位区间，B/W/D/L 的编号乘以对应位宽；已有变量类型比地址宽时按两者最大范围预留。有限地址空间，耗尽则整体失败。不移动既有地址，保留手工名称；自动名称使用合法 ASCII 从站名、方向及 PDO 索引/子索引并避开现有 IO/轴名称（不区分大小写）。无法解释的既有地址阻止分配并说明。

新增从站与自动映射在一次 ChangeHardware 中提交或回滚，失败不留下半个从站。选中从站新增“补全 IO 映射”按钮供旧工程和新勾选 PDO 使用，幂等且不删除/覆盖映射。不自动生成 ST 变量声明，不改变设备配置；所有地址仍为离线工程描述。

IO 映射采用 Avalonia 原生 ListBox 加固定表头和 Grid 行模板实现表格，不引入新依赖。保留 IoMappings 控件和 SelectedIndex 顺序，现有编辑按钮继续可用；列为变量名、地址、类型、方向、从站、PDO，提供横向/纵向滚动。刷新后保持正确选择。左侧节点用专用标识和点击处理，切换硬件页、展开 IO 区并滚动至表头；重复点击、键盘选择也能导航，不弹出文件或修改工程。

验证覆盖多从站、混合类型、位打包/对齐、大小写/重复地址、既有较宽类型、幂等补全、未知类型提示、失败回滚；实际 UI 表头/行选择编辑、导航/重复点击/折叠展开、保存重开和完整桌面回归。
