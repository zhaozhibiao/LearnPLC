# 下载默认应用程序

用户要求下载后默认激活；需要重启核心时明确提示，完成后保留原运行/停止状态。当前固定 OpenPLC 安装切换程序需要重启 Runtime 服务，PLC 程序必须先停止。采用下载编译成功后一次确认，再自动停止（若原程序运行）、激活和核对状态的流程。原程序运行时，在新程序停止及身份确认后启动新程序并再次核实运行状态；原程序停止时保持停止。取消确认只保留已编译候选，不停止旧程序。不连接或操作现场设备验证。

主按钮改为“下载 / 应用程序”，串联现有暂存、Linux 编译、就绪检查、查询身份、重启提示、重新核对身份、停止、激活、状态核实。辅助按钮改为“应用已编译程序”，用于取消后继续应用，不再使用“显式激活”术语。初次空设备基线和已有设备登记规则不变。

确认弹窗必须包含目标、当前是否运行、停止程序和重启 Runtime 核心、在线监视短暂断开，以及完成后自动恢复运行或保持停止；弹窗高度允许文字完整展示。当前后端固定 RequiresCoreRestart=true，不虚构无需重启能力。

抽离可测试 ProgramDownloadWorkflow 到 Toolchain，通过 IProgramDownloadHost 提供现有传输、编译结果应用、确认和监视失效回调。冻结候选、工程与连接身份，整个操作持有 busy/deploymentBusy 锁；每次异步边界重新检查。编译失败/运动门禁未就绪/机械离线参数禁止应用时不进入确认或停止。确认前后核对设备活动版本和状态，发生变化拒绝操作；不借查询更新的全局状态默默采用新基线。已是相同活动程序时不重启，返回实际状态。

停止响应必须确认原版本已停止；激活响应与切换后状态必须确认当前候选身份及停止状态。恢复运行前再次核对本地就绪条件；启动响应和最终状态都必须确认当前候选身份及运行状态。任何不明结果、超时、取消连接或失败均不自动重试；可能部分完成时提示先刷新真实状态。已有设备端事务、校验和、备份回滚不变。客户端在当前连接目标或工程变化时不得继续发送停止/激活/运行。

验证：假传输记录完整顺序，包括 running 与 stopped、已激活、取消、编译失败、门禁失败、未登记基线、身份/状态/工程/目标变化、停止失败、激活不明和最终状态失败；所有失败不得继续后续写操作。真实 Avalonia 弹窗验证按钮文案、重启说明、取消/接受和操作期间修改失效；完整桌面与部署回归。新增代码沿用自有 MIT，无新依赖。
