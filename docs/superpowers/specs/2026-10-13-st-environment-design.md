# ST 工程环境设计

日期：2026-10-13。实施目录：`D:\OPenplc`。

状态：已按用户批准实施。ST 真机闭环和桌面采样验证见 docs/verification.md。用户已确认第一版仅支持 ST，不实现 LD/FBD/SFC。

## 1. 已确认目标与现状

提供工程树、ST 编辑、编译检查、程序包生成、Linux 下载编译、明确激活、在线变量及实例监视、趋势、日志、运动功能块和自有硬件组态。

商业目标：自研工程站和自有轴控允许闭源销售；采用第三方组件时履行各自许可证义务。

本目录当前只保留旧教学模拟器 README、技能目录及 Git 元数据，frontend 的受版本管理文件已在工作区删除。保持这些删除，不恢复旧模拟器、不用它代替真实 PLC 执行。

另一个项目位于 `D:\ethercat主站`，现有 Windows 工程站使用 Avalonia/.NET，自有 Linux 核心负责 EtherCAT、轴运动及路径执行。该项目只读参考，本次产品代码均落在本目录。ST 工程是新的独立工程模型，不将另一个项目现有 C/C++ 工程强制迁移成 ST。

## 2. 方案选择

推荐：独立 Avalonia 工程站 + AvaloniaEdit + 独立 ST 编译工具 + OpenPLC Runtime v4 + 自有轴控桥接。与原工程站技术一致，利于复用交互习惯及硬件模型；需要自己实现语言服务、部署协调和桥接。

备选：React/Monaco 工程站 + 本地服务。编辑组件成熟，但增加桌面封装、服务生命周期和另一套界面框架的维护成本。

备选：修改 OpenPLC 官方 Editor。集成更快，但其 GPL 许可与闭源工程站目标不匹配，本方案不采用。

选定方案不重写 ST 编译器，也不将 GPL 编译器源代码、解析器或语义分析器复制到自研工程站。进程边界不是自动取得闭源许可的保证，发行前仍核查独立作品关系和分发义务。

## 3. 模块与依赖

建议目录：

```text

src/StWorkbench.App/        Windows 工程站与 ST 编辑界面

linux/                     部署协调器、轴控桥接及运行侧适配

examples/                  可独立编译的 ST 示例工程
```

核心模型不依赖 UI，不直接调用设备。通信与编译均通过独立适配器。示例设备和真实设备必须明确区分；缺少真实连接时不能显示下载、激活或运动成功。

## 4. 工程及 ST 编辑

工程使用带 schemaVersion 的 JSON 清单，源程序保存为独立 UTF-8 `.st` 文件。稳定 ID 标识程序、函数、功能块、数据类型、全局变量、任务、硬件资源和轴引用；改名不改变对象身份。

工程树支持上述分类、创建、改名、删除、保存、打开以及未保存提示。保存采用同目录临时文件及原子替换；无效工程不得覆盖原文件。禁止工程内相对路径逃逸、重复 ID 和忽略大小写的命名冲突。

编辑能力：ST 关键词/注释/字符串高亮、行号、缩进、撤销、工程符号补全、功能块输入输出提示、跳转定义、错误列表和点击定位。轻量词法索引负责编辑帮助，外部编译器负责权威语法和类型诊断；词法检查通过不能称为编译成功。

第一条运行闭环使用一个周期任务。工程模型保留多任务配置；未完成运行版本能力及调度测试前，明确拒绝多个启用任务，不静默合并、不只实现一个任务却展示多个已运行任务。

## 5. 构建、下载、激活与上传

构建身份至少包含工程 ID、源文件哈希、编译器版本、Runtime 兼容信息、符号表哈希、硬件映射哈希和运动接口版本。构建输入取不可变快照；编辑器继续修改不改变已生成的程序包。

流程：检查工程 → 外部 ST 编译 → 生成 Runtime 认可的源代码/运行接口/调试数据 → 生成及校验程序包 → 上传暂存版本 → Linux 编译 → 验证候选版本 → 用户选择激活 → 核验当前激活身份。运行是独立操作。

状态分别显示：未检查、检查失败、生成中、上传中、编译中、编译失败、编译成功未激活、激活中、已激活未运行、运行中、结果未知。超时及失联后查询服务端实际状态，不能用本地猜测宣告成功，也不能自动重发有副作用的操作。

Runtime 官方文档存在旧 iec2c 路径与新 STruCpp 路径描述差异。必须锁定实际 Runtime/编译器提交，按该版本源代码验证包格式、导出符号和调试 ABI；不能仅按文档拼 ZIP。

必须先验证原生上传是否影响活动版本、是否自动停机/切换及能否可靠回滚。若不支持独立暂存、编译和激活，Linux 部署协调器承担隔离候选构建、停止确认、原子切换和失败恢复；验证前禁用活动设备下载，不能在 UI 中虚构独立激活能力。

激活前确认 PLC 停止及自有核心停止策略已确认，校验硬件/轴资源版本，保留上一个可运行版本。编译失败不替换活动版本。进程重启后从持久化事务记录恢复状态，不能自动开始运动。

设备上传回工程站：仅在设备保存完整源工程时恢复；缺少源文件时明确说明只能读取版本和产物，禁止声称可从二进制还原 ST。覆盖本地工程前比较身份及未保存修改。

## 6. 在线监视

调试会话绑定构建身份、符号表身份和运行会话。身份不一致拒绝绑定变量，提示重新构建/下载或选择匹配工程。

变量监视支持类型、值、实例路径、采样时间与质量标记。结构、数组和 FB 实例按需展开。通信中断、过期、读取失败和不支持的类型标为不可用，不能补零。

趋势使用有容量限制的采样缓存和采样序号，缺样形成间断，区分设备采样时间与工程站接收时间。运行日志可选择、复制和筛选，带来源、时间和版本上下文。

首版在线只读，不提供强制变量、暂停实时线程或带轴动作的单步运行。调试采样不得阻塞 PLC 扫描或 EtherCAT 周期。

## 7. 运动与硬件

自有实时核心独占 EtherCAT、PDO、CiA402 和插补。OpenPLC 执行工艺逻辑；ST 不直接操作 EtherCAT 驱动，也不按 PLC 扫描周期逐点发送轴位置。

已有 SDK 具备快照读取、控制权租约、轴命令、路径查询/下载及按 ID/版本启动能力。桥接适配实际协议，不假定它已经支持共享内存；优先核验有界异步通道和现有本机协议。

功能块目标：`MC_MoveAbsolute`、`MC_Home`、`MC_Stop`、`EC_ExecutePath`，输入使用稳定轴引用或 PathId + PathVersion，状态包含 Busy、Done、Error、ErrorID 和关联请求 ID。命令提交采用 Execute 上升沿；同一 Execute 高电平不得每扫描重复发送。功能块是 PLCopen 风格接口，未做完整一致性验证前不宣称 PLCopen 认证或完整标准兼容。

桥接以会话/请求序号关联受理、应用和动作完成；完成事件锁存到消费。控制权冲突、队列满、反馈过期和失联应产生明确错误。扫描路径不等待网络往返；租约续期由桥接管理。运行停止和失联策略按实际控制核心能力测试，不把普通 Stop 当急停。

路径引用绑定不可变版本，未知版本或轴映射不一致拒绝运行，不自动替换为最新版本。

自有界面提供 EtherCAT 从站/ESI 信息、IO 映射、单位、限位、回零参数及轴配置。硬件配置和 ST 符号绑定版本化；输入及系统状态只读，普通输出提交到自有核心统一仲裁。硬件模式的映射无效时禁止激活。

## 9. 实施顺序与验收

1. 工程基础：工程树、文件保存、ST 编辑、外部编译检查；例程包含程序、函数、FB、数据类型和全局变量。验证保存重开一致、未保存保护、错误源位置正确。
2. 真实闭环：锁定 Runtime/编译器兼容版本，验证包 ABI、Linux 编译、候选版本隔离和激活；用计数器程序验证下载、启动及监视值递增。网络失败和编译失败保持已激活程序身份。
3. 在线：符号绑定、实例展开、趋势及日志；验证错误版本拒绝绑定、断线值过期、缓存有界。
4. 自有桥接：在模拟核心验证命令边沿、请求关联、控制权、队列满及租约失效，再进行受控实机定位、回零和路径测试。
5. 硬件及现场：ESI/IO/轴配置版本校验；验证停止、重启、异常程序、断网、断电恢复以及任务超时。测量扫描耗时和 EtherCAT 抖动，保留测试设备、版本、时长及结果。

阶段验收必须分别标记“本地测试通过”“模拟联调通过”“真实 Runtime 联调通过”“轴控实机通过”。未连接 Linux 或实际设备时，不宣称完整可靠版本交付。

第一阶段实施计划在本设计审阅后编写，随后逐阶段实施；不得为快速展示而用正则 ST 转译或前端计数模拟替代正式编译运行闭环。
