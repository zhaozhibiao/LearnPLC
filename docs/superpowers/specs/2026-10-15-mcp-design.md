# ST Workbench MCP 接入设计

状态：用户于 2026-10-15 回复“请执行”，已批准实施。范围包含真实轴运动控制；开发自动验收不连接实体轴执行运动。

## 目标与方案

为支持 MCP 的模型客户端提供同一套 ST 工程、组态、构建、PLC 和轴控工具。纯模型 API 需要宿主转接 MCP；不能承诺所有模型产品都原生支持。

推荐新增独立 .NET MCP 服务，通过标准输入输出连接客户端，复用现有 Core、Toolchain、OpenPlc、Motion 模块及 Linux EcMotion 协议。无需启动桌面窗口，不改变现有界面布局和工程格式。提供启动脚本、客户端配置示例、工具说明和自动验收。

另外两种方案：嵌入桌面可直接操作未保存文档，但模型连接依赖桌面生命周期；HTTP 服务适合多机接入，但必须同时实现认证、会话隔离和连接管理。本轮采用独立 stdio 服务，HTTP 和桌面实时文档同步不纳入本轮。

## 工程与编辑

服务启动时由操作者指定允许的工程根目录、编译器和设备配置，模型不能修改这些服务权限或提供任意命令。所有工程读写限于根目录，拒绝越界、目录联接和符号链接绕过。

以已保存的 .stproj 为交换格式。提供工程创建/读取，程序、函数、功能块、数据类型、全局变量的新增、读取、更新、删除和重命名，以及符号、指令模板查询。重命名须返回引用变更计划，不能仅修改工程树名称而遗留 ST 定义。任务、网络、硬件、IO、轴和路径编辑使用同一事务机制。

读取返回 revision；修改必须提交 expectedRevision，不匹配则报冲突，不覆盖新版本。编辑先保留在服务会话草稿中，结构及引用检查通过后才显式保存。ST 语法或类型尚不完整时允许保留草稿，构建前必须检查通过。保存复用 ProjectStore 的不可变源文件版本和原子清单替换；跨服务实例使用工程级写锁及锁内版本复查。

MCP 不读取或覆盖桌面未保存的编辑器缓冲。返回结果明确提示原界面需重新加载已保存工程；用户须先处理桌面未保存修改。工程文件和设备活动程序始终分别标识，不能将保存显示为已下载。

## 工具分组

| 分组 | 提供能力 |
|---|---|
| 服务发现 | 服务版本、权限、工具使用顺序、运行限制、后端能力 |
| ST 工程 | 工程创建/打开、资源增删改名、源文档读写、符号与模板、差异与保存 |
| 组态 | 周期任务、网络配置、ESI 导入、从站配置、自动 IO 地址分配、IO 表、轴及机械参数 |
| 路径 | DXF 导入、单位倍率、分段/动态参数、离线规划、预计时间、不可变版本预存及查询 |
| 检查与构建 | 工程校验、ST 编译、位置诊断、候选包生成、构建身份和有界日志 |
| 设备 | 已配置设备的状态/能力/日志查询、下载编译、应用、PLC 启停及结果查询 |
| 轴控 | 实际状态/位置/速度、申请/释放控制权、使能/关闭、故障复位、回零、绝对定位、有期限速度运行、受控停止、运动结果查询 |
| 路径执行 | 能力允许时调用已验证的路径 ID/版本；缺失连续运动能力时明确拒绝，不替换成逐点停稳 |

工具提供严格参数结构和结构化结果，包含 operationId、状态、诊断、实际设备身份及可用时的采样时间。长任务提供查询与有界日志，不用长时间阻塞隐藏状态。工具异常成为明确错误，不能用成功文字包装失败。

## 构建与 PLC

复用独立 ST 编译器、候选包生成、SSH 主机身份校验和 Linux 协调器。编译器路径、SSH 用户、主机及私钥由服务启动配置提供，模型不能替换成任意进程或远程命令。密码、私钥及会话凭据不进入工具结果。

下载与应用分开呈现阶段，应用预检返回目标、候选身份、核心重启影响及原运行状态；执行绑定这份短期计划，不允许用旧确认套用新程序。复用 ProgramDownloadWorkflow：原来运行则应用后恢复运行；原来停止则继续停止。设备身份或状态变化时要求刷新计划，通信超时返回结果未知，禁止自动重发激活或启停。

## 真实轴控制

MCP 是上位机指令通道，绝不充当实时轴周期。实时闭环、插补、驱动保护和设备侧看门狗继续由现有 Linux 运动核心负责。新增独立的 Linux 会话适配通道连接 EcMotion 控制端；不伪造 PLC 扫描帧、不占用现有 PLC 私有轴工作进程接口。

真实控制须由操作者在服务启动配置中启用并固定设备与允许的轴；普通工程读写本身不授予设备控制权。用户已要求实现此控制能力，本次验收仍不使能或移动实体轴。

控制请求只能使用项目已配置且与活动设备映射一致的工程轴。修改离线轴参数不表示这些参数已在设备生效。后端当前不支持机械/旋转参数应用确认时，继续阻断相关实机控制；不得绕过现有门禁。

动作前验证新鲜状态、真实后端能力、单位/限位/动态上限、使能/回零要求和控制权。同一轴由 PLC 或其他客户端持有时返回冲突，不抢占。会话由设备租约区分，服务端持续维护有期限会话；模型不承担毫秒级心跳。速度运行必须有明确且有界的持续时间，即使模型不再调用停止也要由设备侧期限/看门狗终止，不能只依赖 Windows 客户端定时器。

回零、定位和速度运行先生成短期动作计划，绑定设备、轴映射、单位、参数和限位摘要；执行只能消费一次，参数或映射变更后失效。使能/关闭、复位和停止同样返回真实请求身份；停止可抢占本会话的忙动作，不能因一般动作排队而延后。此通道提供普通受控停止，不声称具备硬件急停或安全功能认证。

复用 EcMotion v4 身份、序列、租约及完成证明：定位须匹配实际 MotionId；物理回零须校验 native AppliedCycle 及采样周期。Accepted、Running、Completed、Failed、Aborted、Unknown 分开返回；提交成功不表示运动完成。断线或结果不明不自动重连重放，尝试受控停止自有轴并释放租约；设备失联时依赖设备侧租约与看门狗，结果仍须标注未知。

现有基础轴工作进程明确发布 Continuous=false、MotionCycleApplied=false。MCP 必须如实报告；若真实后端无法提供连续插补、动态参数确认或可靠终态证明，对应工具返回 capability_missing。不能通过增加 MCP 工具名宣布这些能力已经接通。

## 验收

1. 使用真实 MCP 客户端启动 stdio 服务，完成能力发现、工具枚举、工程创建、ST 编辑、组态、保存、重开和错误诊断。
2. 验证工程路径越界、联接绕过、过期 revision、多实例冲突、草稿失败不污染已保存工程，以及工具日志不污染标准输出。
3. 使用真实独立编译器编译 ST 并生成与桌面兼容的程序包；坏程序返回准确位置。
4. 使用隔离模拟后端验证下载各阶段和原运行/停止状态保持；通信结果未知时不重试。
5. 使用原项目隔离仿真器和协议测试验证租约冲突、限位、单位、映射变更、重复执行、定位终态、回零证明、速度运行超时停止、断线和设备侧看门狗。仿真结果始终标记非物理。
6. 未支持的实机能力必须在工具结果中明确拒绝。真实运动安装联调另行执行，不在自动测试中连接现有实体轴。
