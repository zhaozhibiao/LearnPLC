# 本项目CSP时序与跟随保护修正方案（2026-10-29）

状态：方案文档。本轮未实施新修复、未试转、未更改现场保护或故障锁存。

## 决策

采用“测量时序 → 修正同步/交付相位 → 建模经验证的残余延迟 → 分层保护 → 分档实机验收 → 正式工程站迁移”。不将继续增益扫描、直接固定3ms补偿、扩大跟随阈值或直接换轨迹规划器作为首要解决手段。

单做DC同步无法处理驱动内部的稳定采样/插补延迟；单做反馈外推无法消除漏周期或不稳定交付。组合方案分别处理两种问题，且使误差判定具有明确物理含义。

依据：本机300rpm试验在约192rpm指令阶段触发主站保护，峰值0.009297rev；峰值帧驱动60F4为383counts，内部需求与反馈差-255counts。该段历史匹配以约3周期残差最小，但不满足认定固定3ms的条件。驱动603F=0、总线OP不能证明指令准时应用。

## 阶段1：固定基线并补齐观测

- 固定已验证二进制c2c7cbdf...、源清单、驱动固件、ESI、PDO、单位、电子齿轮、前馈、环路增益及内核/IgH/网卡版本；记录根服务和普通用户代理状态。
- 未使能核验0x1C32/0x1C33支持的同步类型、周期、复制/计算时间和异常计数；不向未确认对象盲写值。
- 扩展现有有界周期采样：计划唤醒、实际唤醒、收帧/处理/发帧边界、有效参考钟时间/相位、当前及上一发送目标、周期编号、WKC、新鲜度；保留6062/6064/606C/60F4/6077原始整数。
- 核心函数入口/出口时间只表示软件调用时间，不冒充网线上实际时刻；必要时抓包或核验网卡时间戳能力，明确时间戳所在位置。
- 未使能静止数据测通讯时序；低速正反向和匀速/加减速数据测驱动实际需求与反馈延迟，恒定位置本身不能识别动态处理延迟。

通过条件：可以量化尾部抖动、PDO相对SYNC0的到达裕量，区分启动收敛和稳态；否则不进入高速验证。

## 阶段2：修正周期与SYNC0关系

保留1ms基础周期，先不靠改到250us压低数值。

- 初始应用时间、参考钟选择、DC/SYNC0设置和主站激活顺序按现场IgH版本核验。SOEM的函数调用顺序不直接复制到IgH。
- 支持明确选择参考钟跟主站R2M与主站跟参考钟M2R，禁止两个控制方向互相对拉。针对本机优先验证M2R的有界相位闭环；只有参考钟有效、反馈可用且收敛时才允许轴使能。
- 相位控制器的纠偏量受限，使用无堆分配的周期代码；失锁、参考时间不新鲜、跨周期异常计数可观测。
- 根据驱动时序与实际计算/发送时间确定SYNC0 shift，保证PDO在指定消费时刻之前到达；不预设0或半周期必然正确。
- 超周期不通过连续快速执行多次轨迹步来追赶。明确检测迟到、丢周期、重复输入；按状态策略停止或禁止运动，并留下原因。

通过条件：稳态相位闭环收敛，测试窗口中不存在未解释的跨消费周期；生产者/驱动之间的延迟分布稳定且落在声明边界内。具体微秒预算根据测量、设备要求和最坏执行时间确定，不预设通用合格数字。

## 阶段3：将跟随误差定义为同一参考时刻的差值

首选保存“已发布轨迹历史并与反馈采样参考时刻对齐”，而非先把反馈按速度外推。

新增预分配的固定容量参考历史：发送目标、计划应用时刻、发送周期/有效性。延迟参数按轴配置，包含值、允许范围、来源和标定版本；仅在未使能且配置身份一致时应用。不能在每个周期根据误差大小自动选择最有利的历史目标。

e_raw = 上一已发送目标 - 原始位置反馈（保持诊断）。
e_aligned = 对应反馈参考时刻的已发布历史目标 - 原始位置反馈。
e_drive = 驱动60F4原始误差（单独换算与记录）。

非整数周期需要有界插值，轨迹时间戳、暂停、反向、回零重置和计数回绕均有测试。只能修正已测稳定处理链的参考时刻；不能补偿真实负载失跟、丢帧、未收敛时钟或驱动异常。历史不足、时间不单调、超出标定延迟范围、WKC无效时判数据无效并执行保护。

通过条件：用独立低速正反向、多种运动阶段验证模型一致性；未能区分反馈对象更新时刻时不启用补偿。不能直接采用本次相关性最小的3周期。

## 阶段4：保留分层保护，明确阈值含义

- 真实位置跟随：现有0.005rev/20ms阈值用于具有已验证同一参考时刻的e_aligned。
- 原始时差观测：e_raw始终显示、采集。不能把旧的未对齐0.005rev阈值和新对齐阈值混称为相同保护；迁移文档及测试必须说明监视对象变化。
- 指令链路独立监视：受测量约束的时间窗、最大目标增量、数据新鲜度、相位/WKC、延迟范围异常单独保护，不能由误差补偿抵消。必要的原始误差包络根据允许延迟、指令轨迹和机械上限推导，并作为显式安全配置评审，禁止随速度自动无界放宽。
- 驱动器自身跟随、过流、超速等保护保持有效；60F4符号/尺度/更新语义按厂家核实，未知时不混用为唯一安全依据。
- 实际超速、软限位、控制权看门狗和驱动故障不使用补偿后的反馈规避。
- Stop是受控停止请求；Disable是撤使能；故障停机根据故障类型处理。先验证驱动快速停止/撤使能实际行为和停止距离，不将撤使能等同受控减速。PLC停止/Abort仍是状态逻辑，不杀进程停总线。

必须通过的离线故障注入：正常固定延迟、可变延迟超界、真实停转/慢跟、反馈冻结、漏周期/重复帧、速度阶跃、反向、参考钟丢失、回零及重新使能、32位回绕、历史不足。验证模型不会把真实失跟判正常，也不会把已知正常处理延迟误判机械故障。

## 阶段5：分档试验

- 先用相同既有30rpm工况做新旧对照，固定环路/前馈，不同时改增益和轨迹。
- 然后60、120、180、240、300rpm；300rpm通过后600、1000、1500、2000、2500、3000rpm。中间档是自动验收门，失败即停止，不反复Reset强行通过。
- 每档按加减速和稳速时间计算足够行程，验证机械范围、32位目标计数、软限位和停机距离。未达到实际目标速度及稳速观察时间不算通过。
- 验证轴物理一转和实际转速，核对反馈与外部观察/仪表；同源目标和编码器数字不能独立证明机械换算。
- 每档建议至少三次往返，并包含启动、加减速、稳速、反向、受控停止和撤使能收尾。短测通过后增加长运行观察，不将单次无报警等同额定全速能力。
- 同时报原始误差、对齐误差、60F4、实际达到转速、转矩/电流、尾部周期抖动、相位、WKC和异常计数。3000rpm下的超速/电流上限依据铭牌、驱动参数与停止能力确定，不按低速测试值简单放大。

目前不改变驱动增益。若时序和误差语义正确后60F4仍显示真实失跟，才针对测量结果调环路/前馈；若加速冲击成为主因，再独立评估jerk受限规划。Ruckig不是当前第一步。

## 阶段6：工程站正式迁移

前提：300和3000rpm均达到明确验收标准。

1. 从工程站本地找回匹配的项目源、任务、硬件/轴组态和路径资源。设备旧候选源包缺失时，不能伪造相同buildHash或用诊断包冒充正式程序。
2. 正式构建流程纳入修复及回归，生成新软件/硬件/程序身份；增加轴时延模型和同步配置的版本绑定，防止驱动参数改变后沿用旧标定。
3. 使用现有root常驻硬件代理部署固定哈希核心，普通用户工程通道保持原权限边界，不扩展为任意root执行入口。
4. 通过正式硬件下载及程序下载流程应用；保持原先运行/停止状态，并保留正常在线、监控和上传。测试台架的±25rev、临时原点及升速限值不默默覆盖正式工程。
5. 在线显示轴Ready/Busy/Done/Error及原始/对齐/驱动误差，底层诊断放在属性/诊断界面，不要求用户额外写大量ST。
6. 验证重启恢复、程序下载、硬件单独下载、正常Stop/Disable时总线不中断；保存旧二进制、配置、程序身份和驱动SDO快照，支持完整回退而非仅回退可执行文件。

## 实现边界

优先新增cycle_timing、motion_reference_history独立模块，在main.cpp、axis_feedback.cpp、motion_safety与trace字段中做受控集成；修改通过精确源码叠加/清单进入正式构建，不仅保存在artifacts目录。驱动器厂家特性归入轴/硬件配置，核心保持通用CiA402接口。
